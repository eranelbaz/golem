# M3.5 benchmark gate (A4) — GLM-5.3-Flash UD-Q4_K_XL on RX 7900 XTX

Single-run numbers except where noted; cold and warm reported separately. All
decode/prefill tok/s come from the golem process's own per-turn wall-clock
lines (`[m35] prompt_tokens=N chunk_cap=C prefill_ms=P gen_tokens=G decode_ms=D`,
temporary bench instrumentation in `session.rs::chat_turn_inner` + a
`[m35]` REPL line in `run.rs`, reverted after the run and never committed).
Re-measure after any hot-path change.

## Environment

- Machine: AMD Ryzen 9 9950X3D (32 threads), 93 GiB RAM, memlock 80 GiB,
  RX 7900 XTX (Navi 31, gfx1100), 24 GiB VRAM.
- ROCm 7.2.4, kernel `7.2.5-4-omarchy`, NVMe model drive (`/mnt/data`, 916 GB).
- Model: `GLM-5.3-Flash-UD-Q4_K_XL-00001-of-00006.gguf` (6 shards, 186 GiB,
  expert tensors 185,478,414,336 B = 172.8 GiB). Shape check: 42 live MoE
  layers (+1 MTP layer skipped at load) × 288 experts × 3 planes = 36,288
  planes → 172.8 GiB / 36,288 ≈ 5.0 MB avg/plane, consistent with the
  ~4.7/5.8 MB up·gate/down plane sizes.
- Commit: `658c3d3` (branch `review`). Release build, HIP substrate
  (backend=hip verified in `golem-llama-sys` build output; `libamdhip64.so.7`
  linked). Engine defaults elsewhere (`--threads` unset → 16, `--ctx` 256,
  `--n-predict` 64, greedy).
- Cold = all 6 shards `posix_fadvise(DONTNEED)`'d (`scripts/evict-model-cache.py`)
  immediately before launch. Warm = immediate re-run with page cache intact
  (see warm-leg caveat below). Every run via `nohup … > log 2>&1 &` + polling.

## Leg D-1: pooled GPU-only vs upstream-style unpooled CPU-hybrid

Commands (identical except `--ram-experts-gib`):

```
target/release/golem run --greedy <shard-00001> \
  --n-gpu-layers 99 --cpu-moe-layers 99 [--ram-experts-gib 10 | --ram-experts-gib 0]
```

Two turns per process over stdin REPL: short prompt (13 prompt tokens) and a
162-token prompt. `n_predict` cap 64; turn 1 stopped at EOG after 36 tokens.

### (a) Golem pooled, 10 GiB mlocked pool

| Metric | cold run 1 | cold run 2 | warm |
|---|---|---|---|
| t1 prefill (13 tok, cap=1) | 43.3 s → 0.30 tok/s | 43.1 s → 0.30 tok/s | 25.4 s → 0.51 tok/s |
| t1 decode (36 tok) | 98.2 s → 0.37 tok/s | 96.2 s → 0.37 tok/s | 43.6 s → 0.83 tok/s |
| t2 prefill (162 tok, cap=1) | 677.7 s → 0.24 tok/s | 738.4 s → 0.22 tok/s | 346.8 s → 0.47 tok/s |
| t2 decode (64 tok) | 194.9 s → 0.33 tok/s | 159.4 s → 0.40 tok/s | 158.4 s → 0.40 tok/s |

Single runs; cold shown twice to expose variance (decode 0.33–0.40 tok/s band).
`chunk_cap=1` in every pooled `[m35]` line (K=10, top-k=8), confirming the A1
cap on the real model. Pooled preflight accepted 10 GiB: memlock 80 GiB,
75%-of-free-RAM cap satisfied on fresh-cache runs.

### (b) Upstream-style unpooled (`--ram-experts-gib 0`, experts CPU_Mapped/mmap)

Not completable in practical time on 93 GiB RAM; thrash-dominated. Measured:

- Cold: turn 1 emitted ~12–18 tokens in ~40 min (≤0.2 tok/s), then collapsed
  to zero output for 13+ min while still burning 89% CPU and ~322k major page
  faults/s (vmstat), effective shard read rate decaying 267 → 58 MB/s, GPU 3%
  busy. Killed at 50 min; no `[m35]` line ever printed.
- Warm attempt (83 GiB of shard pages cached from the killed cold run): same
  signature — 2 pieces in 13.6 min, 90% iowait, ~33k majflt/s. Killed.
- Cross-check: the M0 baseline measured upstream `llama-cli -ngl 99 -ncmoe 45`
  on this box at **0.6 tok/s generation** (`docs/baselines/m0-notes.md`,
  `probe-ncmoe45`), consistent with the 0.05–0.2 tok/s partials above.

Verdict the numbers support (ruling is the user's, not recorded here): the
pooled path is ~2–5× the unpooled path cold and completes; unpooled is
unusable both cold and warm at this RAM footprint because the 172.8 GiB
expert working set exceeds 93 GiB RAM and mmap major-faults thrash.

## Leg H-4: pinned vs pageable H2D GB/s

Harness `crates/golem-llama-sys/tests/pinned_h2d_bandwidth.rs` (plane sizes
4.7/5.8 MB + 64 MiB bulk, 20 timed synchronous `hipMemcpy` H2D each, warmup
excluded). Two consecutive runs:

```
GOLEM_LLAMA_SYS_BACKEND=hip cargo nextest run -p golem-llama-sys pinned_h2d --success-output=immediate
```

- Run 1: 4.5 MiB pinned 27.01 / pageable 26.83 GB/s (1.01×) · 5.5 MiB pinned
  27.56 / pageable 27.14 (1.02×) · 64 MiB pinned 28.29 / pageable 28.59 (0.99×)
- Run 2: 4.5 MiB pinned 26.77 / pageable 26.69 (1.00×) · 5.5 MiB pinned 27.52 /
  pageable 26.46 worst=12.92 (1.04×) · 64 MiB pinned 28.34 / pageable 28.60 (0.99×)

Raw `hipMemcpy` bandwidth is pinned≈pageable at 27–28.6 GB/s (PCIe-class
plateau) on this ROCm; pinned's advantage shows up only as stability (pageable
threw one 12.9 GB/s outlier). H-4's engine-level rationale (registration
amortization, no per-copy staging) is not visible as raw memcpy GB/s here.

## Leg 3: cold prefill tok/s at the A1 chunk cap

`chunk_cap = max(1, K/top_k) = 1` (K=10 derived from free VRAM, top-k=8), so
the 162-token prompt prefills as 162 single-token ubatches, each routing the
near-full expert set. From pooled cold run 1, turn 2:
**162 tok / 677.7 s = 0.24 tok/s** (cold run 2: 0.22; warm: 0.47). This is
the number the prefill-excluded-from-scoring decision (§6.2 / A1/A3) taxes
every multi-chunk cold prompt with.

## Leg O6/R-2: MTP speculative decoding

**Not runnable.** `rg -i "\bmtp\b" crates` finds only load-time exclusion code
(`sanity.rs` nextn skip, `pool/source.rs` MTP-block exclusion) — no draft
model, no speculation loop, no acceptance-rate surface exists anywhere in the
workspace. Nothing to measure; the O6 decision has no golem-side numbers from
this machine, only the design's estimate.

`/tmp/a4/`: `l1a-cold.log`, `l1a-warm1.log` (cold replicate), `l1a-warm2.log`

Caveats:

- Warm pooled leg: unpooled leftovers left <13 GiB memfree and the pool
  preflight caps at 75% of *free* (not available) RAM; to launch without
  breaking warmness, a 4 GiB byte-range (mid shard 2, ~2% of expert bytes) was
  range-evicted via `posix_fadvise` before the warm run. Impact bounded to
  first-touch disk reads of that range.
- `n_predict` is the engine default 64; turn 1's 36 tokens is EOG, not a cap.
- Upstream-style leg used `--cpu-moe-layers 99`, which at this pin is
  whole-tensor CPU_Mapped for every block — the feasible equivalent of
  `-ncmoe 45` (N ∈ {43,44,45} per M0; N≤42 OOMs VRAM, larger N is identical
  here because all blocks are already CPU_Mapped).
