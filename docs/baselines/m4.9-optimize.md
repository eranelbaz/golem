## Arithmetic (target)

- Exclusive entry: one reservation of pool 63 + snapshots 4 + staging 3.7 +
  host 2 = 72.7 GiB planned RAM; a child registering again would need
  145.4 GiB > 93 GiB and be refused, so children register nothing.
- Memory return check between candidates: `Mlocked` within 256 MiB of the
  pre-sweep reading, else the sweep stops (a leaked 63 GiB pool is far
  outside it). Free VRAM is shared with the desktop: a reading still low
  after 30 s is warned about and becomes the new reference, and the sweep
  stops once the total drop exceeds 1 GiB (≈ 4% of 24 GiB). The profile
  records the lowest free VRAM any candidate ran with.
- Wall clock: default axes on 16 physical cores, one NUMA node, manifest +
  derived K = threads {8, 12, 16}, o_direct {f, t}, io_depth {1, 2},
  io_threads {0, 4, 8}, vram_experts_frac {1, .75, .5}; values equal to the
  effective default (threads 8, o_direct f, io_depth 1, io_threads 0,
  frac 1) are the baseline, not candidates → ≤ 1 + 2·(2+1+1+2+2)
  = 17 measurements per pass (each candidate paired with the incumbent),
  each = load L + ≥ 6 turns (1 cold + warm-up + 5 measured). Load L is
  measured on the first and printed; `--max-minutes 120` bounds the run.
  A measurement (or a candidate/incumbent pair) starts only if the longest
  measurement so far still fits before the deadline; a stop keeps the best
  winner so far, unconfirmed.
- First measured baseline (2026-10-10, ctx 262144, pool 62 GiB): one
  measurement = 722 s wall → 17 measurements ≈ 205 min per pass; two passes
  plus 2 confirmation runs ≤ 36 × 722 s ≈ 7.2 h, so a full sweep needs
  `--max-minutes` ≥ 435.
- NUMA axis: one node on the target → not swept (implemented, untested on HW).
- `async_h2d`: no dedicated copy stream in the vendored scheduler; the knob
  is refused at load and not swept. *Amended 2026-10-13:* the hook ABI v15
  copy stream makes it sweepable; not yet measured.
