# Serve routing trace vs the m3.7 replay (issue #147)

Machine and model as `m3.7-policy-replay.md` (RX 7900 XTX, 24 GiB VRAM,
93 GiB RAM; GLM-5.3-Flash UD-Q4_K_XL, shard-1 `00dceaf3`).

## Capture

One `golem serve` session, 4 chats × 2 turns, `max_tokens` 512, temperature
0.7 (seeded), every turn ran to `length`:

```
golem serve <shard-1> --n-gpu-layers 99 --cpu-moe-layers 99 \
  --ram-experts-gib 59 --manifest <manifest> --ctx 4096 --n-predict 512 \
  --routing-trace serve1.tsv --timing-csv serve1.csv
```

- Resolved K = 19 slots/layer (m3.7: 18).
- 8 turns × 511 = 4,088 decode steps; 171,696 `dc` records = 4,088 × 42, so
  no rows were dropped.
- Mean step 565 ms (1.77 tok/s) across the 4,088 timing rows.
- Trace committed as `traces/serve/serve1.tsv.gz` (2.5 MB). To get one file
  per turn for leave-one-out, split it at each `dc`→`pf` boundary.

The second turn of each chat re-sends the history, so with snapshots its
prefill is only the delta. These traces carry real multi-turn reuse, which
the `run` traces could not.

## Verdicts

- **The routing profile stays deferred.** Over a whole turn it moves d by 0.1
  points (19.2 → 19.1), the same as m3.7. The early-window gain is larger on
  serve (2.2 points vs 0.9 on m3.7), but prefill-stream (#49) still bypasses
  the pool, and pre-filling still costs one pool's worth of reads before the
  first token.
- **#120's ranking holds.** Serve traffic is ≈1.2 points harder at 63 GiB
  (19.2 vs 18.0), and VRAM hit is 1–2 points lower. Every policy keeps its
  place: exclusive + decay best (−4.0 points vs current), then exclusive
  CLOCK (−1.6) and VRAM decay (−1.5), with RAM-only decay the smallest gain
  (−0.4).
- **Warm continuity barely helps.** Replaying the session as one trace gives
  19.1% vs 19.2% cold per turn at 63 GiB, so cross-turn reuse in this traffic
  does not change the tier ranking.
