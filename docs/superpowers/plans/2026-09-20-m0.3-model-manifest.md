### Task 2: Manifest builder script

**Files:**
- Create: `scripts/m0.3-manifest.py`

**Interfaces:**
- Consumes: shard `.gguf` files in a directory; vendored `gguf-py`.
- Produces: `manifest.json` (design §4.2 schema) written next to the shards; schema consumed by M3.1 `golem-store` and M3.2 `golem pull` regression (must re-produce this manifest diff-clean).

Builder behavior (exact):
1. Args: `m0.3-manifest.py <dir> <name> <repo> <revision> <quant> [--replica PATH ...] [--header-only]`. `<dir>` is the **inner** quant dir holding the `.gguf` files (see Locations).
2. Reads every `*.gguf` in `<dir>` (sorted); refuses `mmproj*` names with exit 1.
3. Streams each file through `hashlib.sha256` (1 MiB chunks); records exact on-disk byte size.
4. Opens shard 00001 (smallest, header-only shard) with `gguf.GGUFReader`; asserts `general.architecture == "glm5next"`.
5. Builds `expert_index` by walking the tensor tables of **every** shard (shard 1 has no tensor entries — split-GGUF convention): all tensor names matching the upstream MoE regex `ffn_(up|down|gate|gate_up)_(ch|)exps` (design §4.2); for each, layer = number between `blk.` and `.ffn_`, experts = `*.expert_count` header value, `bytes_per_expert` = tensor `n_bytes` / experts (assert exact division — design §4.3 check 2), `offsets_bytes` = per-expert offsets relative to the tensor's data start (gguf-py `ReaderTensor.data_offset` is shard-relative; §4.2 offsets are tensor-relative). Emits offsets as `i * bytes_per_expert`.
6. `chat_template_sha` = sha256 of the `tokenizer.chat_template` header string, hex-encoded.
7. Writes `manifest.json` with keys exactly: `name`, `repo`, `revision`, `quant`, `arch`, `shards` (each `{file, bytes, sha256, replicas}` — replicas = `[<dir absolute path>, *--replica args]`), `expert_index` (each `{tensor, layer, experts, bytes_per_expert, offsets_bytes}`), `chat_template_sha`.

- [x] **Step 2: Verify the expert-classifier regex and uniformity assertions against the real Q4 shard 1 header only** (header read does not require the download to be complete, only shard 1 + header presence; if shard 2+ are still downloading, run the header-inspection dry mode `--header-only` which skips hashing and prints the expert_index summary + layer/expert counts instead of writing the manifest).
