# M3.8 evidence — per-model hook context + batched readback (issue #50)

Machine: RX 7900 XTX (gfx1100), ROCm 7.2.4, 24 GiB VRAM, 93 GiB RAM.
Fixture for measured legs: tiny-moe-320 (1 expert layer, 8 experts, top-k 2, K=8).
Target arithmetic: GLM-5.3-Flash UD-Q4_K_XL — 42 expert layers × 288 experts × 3 planes
(~4.7/5.8 MB per plane), 6 split shards.

## FFI calls per decode token

| callback | before (ABI v4, base commit) | after (ABI v5) |
|---|---|---|
| notify_access | 1 per routed expert ≈ 42 layers × 2 (top-k) = **84/token** (GLM: × top-k 8 ⇒ **336**) | **0** (callback removed) |
| policy_query | 1 per expert tensor ≈ 42 × 3 planes = **126/token** | **0** (merged into routing) |
| routing readback | — | **1 per offloaded MoE layer** ⇒ 42/token on GLM |
| ensure_host_resident | up to 1 per expert plane per cold layer ≈ **24/token** fully cold (8 experts × 3 planes, one layer) | **1 per (layer, step)** ⇒ ≤ 42/token on GLM; whole miss list submitted to the shared queue at once (8 × 15.2 MB ≈ 122 MB cold layer: ≈61 ms at the M3.5-measured ≈2 GB/s QD1 vs ≈14 ms at both drives' 8.05 GiB/s) |
| copy_done | 1 per compute | 1 per compute (unchanged) |

After-counts are enforced by `crates/golem-engine/tests/p3_counters.rs` (per decode step:
routing == offloaded layers, P3 == 1 per layer with misses, copy_done == 1, and the
per-expert callbacks no longer exist in the ABI). Before-counts are read off the base
commit's call sites (`ggml-backend.cpp` v4: notify_access loop per routed expert,
policy_query per tensor, ensure per pending expert) — structural, not re-measured.
