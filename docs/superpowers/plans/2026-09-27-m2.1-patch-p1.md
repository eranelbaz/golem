**Goal:** Land fork patch P1 (C-ABI policy hooks + expert metadata in `ggml-backend.cpp`) with zero behavior change when hooks are unset, gated by an in-repo T4 check (upstream ctest green + unset-hooks byte-identical parity dump on tiny-moe) wired into CI.

**Architecture:** The vendored fork (`vendor/llama.cpp`, squashed-vendor convention) gains `ggml/include/golem-hooks.h` (moved from the crate-local stub) and a surgical, all-null-guarded section in `ggml/src/ggml-backend.cpp`: three hook function pointers settable via `golem_register_hooks`, plus pure query functions that derive per-tensor expert metadata (expert count, per-expert stride in bytes) from tensor dims + names at weights-buffer-usage time. T4 = upstream `ctest` on the CPU build + sha256 equality of a `golem-cli --parity-dump` run on tiny-moe before vs after the patch.

**Tech Stack:** C/C++ (vendored llama.cpp at pin `86ebfef2`), Rust (`golem-llama-sys` bindgen over `llama.h` + `golem-hooks.h`), cmake crate build, bash gate script, GitHub Actions CI, Python parity suite driver (M1.4).

**Spec:** `docs/tech-design.md` §3.4 (P1 paragraph) and §12.2 row T4; board task M2.1 in `docs/worklog.md`.

## Global Constraints

- **Byte-identical invariant:** with all hooks unset, patched-substrate decode behavior must be indistinguishable from pristine. All new C code paths are behind null-pointer guards or pure query functions with no side effects.
- **Patch discipline (design §3.2):** total vendor diff stays ≤ ~1,000 lines and confined to `ggml/src/ggml-backend.cpp`, `ggml/include/golem-hooks.h`, and the vendor `ggml/src/CMakeLists.txt` (header list).
- **Vendor tree:** never add nested `.git`; every vendor edit requires recomputing `vendor/VENDOR_SHA` (`content_sha256`, `file_count`) and `engine/llama-cpp.lock` `content_sha256`/`patches`. The recompute recipe is the `cs()` function in `.github/workflows/vendor-pin.yml`.
- **ABI:** existing three hook signatures in `crates/golem-llama-sys/headers/golem-hooks.h` are frozen — the vendor header starts from that file verbatim, then adds metadata queries.
- **Rust gates per design §13:** `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo nextest run --workspace`; `unsafe` confined to `golem-llama-sys` + `golem-engine` FFI modules.
- Conventional Commits; plan doc + checkbox updates travel in the same PR; worklog board line fixed in the same task (local-only file, not committed).
- tiny-moe fixture: 2-layer / 8-expert GGUF generated by `xtask gen-tiny-moe` (vocab N_VOCAB 320).

```c
// --- golem P1: policy-hook plumbing (design §3.4). All behavior is behind
// null guards; with hooks unset every code path here is a pure query. ---
#include "golem-hooks.h"

static golem_ensure_host_resident_fn golem_h_ensure_host_resident = NULL;
static golem_policy_query_fn        golem_h_policy_query        = NULL;
static golem_notify_access_fn       golem_h_notify_access       = NULL;
static void *                       golem_h_ctx                 = NULL;

void golem_register_hooks(golem_ensure_host_resident_fn ensure_host_resident,
                          golem_policy_query_fn policy_query,
                          golem_notify_access_fn notify_access,
                          void *ctx) {
    golem_h_ensure_host_resident = ensure_host_resident;
    golem_h_policy_query         = policy_query;
    golem_h_notify_access        = notify_access;
    golem_h_ctx                  = ctx;
}

/* Expert weights in glm-arch MoE models are 3-D tensors whose names end in
 * ffn_{gate,up,down}_exps (upstream names are blk.%d.ffn_*_exps,
 * llama-arch.cpp:450-453): [n_embd, n_ff_exp, n_expert]. One expert is one
 * ne[0]×ne[1] plane: per-expert bytes = ne[0]*ne[1] * type_size / blck_size
 * (ggml_type_size is per-BLOCK, ggml_blck_size is elements per block; they
 * cancel for F32). Fused ffn_gate_up_exps is deliberately excluded — P2
 * splits routed gate/up/down ranges independently. */
static int golem_name_ends_with(const char *name, const char *suffix) {
    size_t nl = strlen(name), sl = strlen(suffix);
    return nl >= sl && strcmp(name + nl - sl, suffix) == 0;
}

static int golem_tensor_is_expert(const struct ggml_tensor *t) {
    if (t == NULL || ggml_n_dims(t) != 3) return 0;
    return golem_name_ends_with(t->name, "ffn_gate_exps")
        || golem_name_ends_with(t->name, "ffn_up_exps")
        || golem_name_ends_with(t->name, "ffn_down_exps");
}

int32_t golem_tensor_expert_count(const void *tensor) {
    const struct ggml_tensor *t = (const struct ggml_tensor *) tensor;
    return golem_tensor_is_expert(t) ? (int32_t) t->ne[2] : 0;
}

int32_t golem_tensor_expert_stride_bytes(const void *tensor) {
    const struct ggml_tensor *t = (const struct ggml_tensor *) tensor;
    if (!golem_tensor_is_expert(t)) return 0;
    return (int32_t) ((uint64_t) t->ne[0] * t->ne[1]
        * ggml_type_size(t->type) / ggml_blck_size(t->type));
}
```
Verified against the project's own fixture: `xtask/src/tiny_moe.rs` tests pin gate dims as `{32,16,8}` (n_embd=32, n_ff_exp=16, n_expert=8) and down as `{16,32,8}` — an expert is one `ne[0]×ne[1]` plane. Notes for the implementer: keep the three hook pointers *unused* in this patch besides assignment — P2/P3 consume them; that is deliberate (design §3.4 splits the seam from its consumers). The three hook pointers are assigned by the non-static `golem_register_hooks`, so no unused-static warning fires; no `golem_hooks_active()` helper is needed in P1 (add it in M2.3 when Rust registers real hooks).
