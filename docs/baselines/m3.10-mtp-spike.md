# M3.10 MTP spike: union ratio gate (#53)

Data: `docs/baselines/traces/m3.7/rt1..4.tsv.gz`, decode rows only, 42 MoE layers,
top_k 8, ≈85k windows per k per trace. U_k = |union of routed experts over k
consecutive decode tokens| / top_k, per layer (plane sizes are uniform, so U_k
is the bytes multiplier of a k-token verify pass).

| k | U_k mean | p50 | p90 |
|---|---|---|---|
| 2 | 1.708 | 1.750 | 2.000 |
| 3 | 2.334 | 2.375 | 2.875 |
| 4 | 2.910 | 2.875 | 3.625 |

Gate (design O6): expected tokens per pass ÷ U_k ≥ ≈1.4. A k-token pass yields
at most k tokens (every draft accepted), so the ceiling is k / U_k:

| k | ceiling at 100% acceptance | at BMoE acceptance (71/60/52%) |
|---|---|---|
| 2 | 2 / 1.708 = 1.17 | 1.71 / 1.708 = 1.00 |
| 3 | 3 / 2.334 = 1.29 | 2.14 / 2.334 = 0.92 |
| 4 | 4 / 2.910 = 1.37 | 2.36 / 2.910 = 0.81 |

The gate fails at every k even with perfect acceptance, so acceptance per position
and tok/s were not measured (user ruling 2026-10-07: gate first, wire only if it
passes). The blk.45 NextN experts would add ≈+2.4% bytes per draft step, which
only lowers the ratios. Decode here is expert-byte bound (d ≈ 0.22, M3.7 A/B),
so the ratio is the speedup bound.

Prompt lookup (n-gram drafts) shares the same verify cost: a 5-token window
pays U_5 > U_4 = 2.91, so it needs ≥ 4.07 accepted tokens per pass to clear the
bar. Not adopted for the same reason; revisit only for verbatim-copy workloads.

**Ruling: reject MTP as a v1 track** (recorded in design O6).
