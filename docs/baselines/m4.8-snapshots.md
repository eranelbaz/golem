# M4.8 state snapshots — turn-N TTFT baseline

**Status: not measured yet.** The harness exists; the numbers do not. Do
not cite this file for a performance claim until the table below is filled.

## Arithmetic (real target)

Snapshot = 145.56 MiB recurrent + 19,712 B/token KV: 8k tokens ≈ 300 MiB,
32k ≈ 761 MiB, 100k ≈ 2.0 GiB. Floor = `parallel × snapshot_bytes(ctx)`;
default = `max(2 GiB, 2 × floor)`. RAM fit at 83 GiB free: 79 − (pool 63 +
staging 3.7 + host 2) = 10.3 GiB ≥ default 4.0 GiB at 100k / parallel 1.
Expected restore of ≈ 300 MiB from pinned memory ≈ 12 ms at 25 GB/s, vs tens
of seconds to re-prefill 8k tokens cold (§2.4). Pinned restore bandwidth is
unmeasured.

## Harness

`crates/golem-engine/tests/snapshot_tiny_moe.rs::hw_snapshot_turn_ttft`:
a 5-turn chat, `--snapshot-ram-gib` 0 vs 2, a fresh session each (cold pass),
then a second pass on the same session (warm). Page cache evicted before each
order with `scripts/evict-model-cache.py`.

```sh
M=~/models/glm-5.3-flash-ud-q4k-xl/UD-Q4_K_XL/GLM-5.3-Flash-UD-Q4_K_XL-00001-of-00006.gguf
python3 scripts/evict-model-cache.py "$(dirname "$M")"/*.gguf
GOLEM_HW=1 GOLEM_HW_MODEL=$M GOLEM_HW_ORDER=off,on \
  cargo nextest run -p golem-engine --features hip-tests --run-ignored all --no-capture hw_snapshot
python3 scripts/evict-model-cache.py "$(dirname "$M")"/*.gguf
GOLEM_HW=1 GOLEM_HW_MODEL=$M GOLEM_HW_ORDER=on,off \
  cargo nextest run -p golem-engine --features hip-tests --run-ignored all --no-capture hw_snapshot
```
