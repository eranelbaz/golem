## Arithmetic (target)

- Exclusive entry: one reservation of pool 63 + snapshots 4 + staging 3.7 +
  host 2 = 72.7 GiB planned RAM; a child registering again would need
  145.4 GiB > 93 GiB and be refused, so children register nothing.
- Memory return check between candidates: free VRAM and `Mlocked` within
  256 MiB of the pre-sweep reading (≈ 1% of 24 GiB; a leaked 63 GiB pool or a
  6 GiB device cache is far outside it).
- Wall clock: default axes on 16 physical cores, one NUMA node, manifest +
  derived K = threads {8, 12, 16}, o_direct {f, t}, io_depth {1, 2},
  io_threads {0, 4, 8}, vram_experts_frac {1, .75, .5}; values equal to the
  effective default (threads 8, o_direct f, io_depth 1, io_threads 0,
  frac 1) are the baseline, not candidates → ≤ 1 + 2·(2+1+1+2+2)
  = 17 measurements per pass (each candidate paired with the incumbent),
  each = load L + ≥ 6 turns (1 cold + warm-up + 5 measured). Load L is
  measured on the first and printed; `--max-minutes 120` bounds the run.
- NUMA axis: one node on the target → not swept (implemented, untested on HW).
- `async_h2d`: no dedicated copy stream in the vendored scheduler; the knob
  is refused at load and not swept.
