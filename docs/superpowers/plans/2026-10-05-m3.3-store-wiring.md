# M3.3 · store-wiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire `golem-store` into the P3 slow path with shared-queue striping (§5.2 amended 2026-10-03), page-cache hygiene (§5.4, H-9), a degraded/fatal-io health state machine (§5.2, §11), and per-step timing CSV — then demonstrate two-drive failover and measure bandwidth A/B on this machine.

**Architecture:** Reads become fixed chunks on one priority queue shared by all replicas; per-**drive** reader threads (1–2, D-12) pull from it, so the faster drive self-selects more chunks (≈72% on nvme0n1/nvme1n1) with no bandwidth probe. A new `StoreExpertSource` (implements the existing `ExpertSource` seam) maps `(layer, kind, expert)` → manifest `(shard, offset, crc)` and drains the queue; `page_in` submits an expert unit's three planes as one batch. Failed chunks requeue with an excluded-replica bitmask; per-replica error counts drive the health state machine. `--timing-csv` records per-decode-step wall/P3-wait/disk/H2D/policy/compute with `unmeasured` for unmeasured columns.

**Tech Stack:** Rust (edition 2024, workspace crates `golem-store`, `golem-placement`, `golem-engine`, `golem-cli`), `std::sync` (Mutex/Condvar + `thread::scope` for disjoint destination slices — no new deps), crc32c (workspace), HIP events for H2D timing via existing `golem-llama-sys` bindings.

**Spec:** `docs/tech-design.md` §5.2 (shared-queue striping, amended 2026-10-03), §5.3 (CRC per expert plane, review D-4), §5.4 (I/O engine, H-9, R-17), §3.4 P3 (layer-batched cold reads), §11 (per-step timing, health states), §12.3 (A/B method). Board row: `docs/worklog.md` §3, M3.3 / issue #26.

**Scope notes (board-line fixes, same PR):**
- The HTTP server does not exist yet (M4), and there is no instance registry / `golem list` subcommand yet either. The health state is therefore surfaced as: (a) a queryable `golem_store::InstanceHealth`, and (b) a `tracing` status line at state transitions on `golem run`'s stderr. The board row wording changes from "`/health` shows `degraded:replica`" to "health state machine reports `degraded:replica` (visible in run log; `/health`/`golem list` mapping lands with the M4 server)". - The per-(layer, step) batched miss list requires the M3.8 P1 ABI bump; until it lands this PR batches an expert unit's three planes (1 queued drain instead of 3 blocking QD1 reads per cold expert). The per-layer call remains #50's acceptance.

## Global Constraints

- Gates per PR: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo nextest run --workspace` — all green before commit is pushed.
- Hot path: no heap allocation, `HashMap` lookup, sort, or mutex per routed expert in P1–P4 callbacks; expert bytes copied at most once disk→pool (reads land directly in the claimed slot's plane regions — no bounce `Vec`).
- One implementation per concern for page-cache hygiene: direct-read with a **runtime** fallback (H-9 — btrfs passes an open-time probe and still returns EIO under concurrent `O_DIRECT`). Reuse `GgufPreadSource`'s per-shard `direct_ok` pattern (`source.rs:278, 531, 650`): the first direct EIO on a replica clears `direct_ok` and that read is served buffered + `POSIX_FADV_DONTNEED` from then on. A direct-read EIO must **not** mark the replica degraded.
- Nothing populates the page cache with expert bytes. No `MAP_POPULATE` of expert tensors.
- CRC32C stays per expert plane (§5.3, D-4), verified after all of a plane's chunks land; never per chunk. Where the manifest's `crc32c` is `None`, skip verification (log once at startup).
- io_uring stays out of v1 (R-17). Default 1–2 reader threads **per drive**, `--io-threads` as override (D-12; t8 measured regressing to ≈2 GiB/s/drive).
- No `unsafe` anywhere in this PR: reader threads are **scoped per drain** (`std::thread::scope`), so chunk destinations cross threads as disjoint `&mut [u8]` sub-slices, never raw pointers and never long-lived threads holding borrowed regions. Spawn-cost arithmetic (below) shows this is negligible at MB-scale ops.
- Errors: libraries return `Result`; no `panic!`/`exit` outside binaries.
- Comments state invariants + design §refs, no plan-task jargon.
- Hardware evidence rules (AGENTS.md): failover demo and bandwidth numbers measured on this machine; arithmetic lines against the real model (42 live layers × 288 experts × 3 planes, ≈4.7/5.8 MB per plane, ≈15.2 MB/unit) accompany every memory/IO decision.
- Every test whose precondition cannot run **fails**, never early-`return`s as pass.

**Interfaces:**
- Produces:
  - `pub const CHUNK: usize = 2 * 1024 * 1024;` and `plan_aligned(base: u64, len: usize) -> Vec<(u64, usize)>` — plans the **aligned covering range** `[align_down(base, 4096), align_up(base+len, 4096))` cut into ≤2 MiB chunks at boundaries `align_down(base) + k·2 MiB`, so every chunk is 4 KiB-aligned in offset and length (O_DIRECT requirement, §5.4) and there is no forced tiny head chunk. Example: a 5,898,496 B plane at file offset 512 → covering range `[0, 2_101_248)` → chunks `(0, 2_097_152)` and `(2_097_152, 4_096)`. The destination for chunk 0 is the region base (head scratch), matching `UnitLayout` region sizing (`source.rs` `UnitLayout::new` already pads regions to `DIRECT_ALIGN`).
  - `pub struct ChunkQueue` — one shared queue; `enqueue` per logical read; demand strictly ahead of prefetch.
  - `pub struct ReadHandle` — returned by enqueue; `wait(self) -> Result<(), StoreError>` blocks until all chunks settle.
  - `pub struct ReadJob<'a>` — **safe** destination contract: the caller passes the plane's full region as `&'a mut [u8]`; the queue splits it into disjoint per-chunk sub-slices (`split_at_mut`) handed to readers inside `std::thread::scope`, so no raw pointer crosses a thread and `golem-store` stays `unsafe`-free.
  - Reader model — **scoped per drain, one thread per physical drive**: a drain (`wait()` on one logical read, or the 3-plane batch of Task 4) takes the queue's eligible chunks for its reads and runs `thread::scope` spawning 1–2 threads **per drive**, each holding that drive's fds for every shard (6 shards × 2 replicas = 12 files; per-drive threads, not per-file — D-12). Threads pull demand-first from a **drain-local work list** — `Mutex<VecDeque<Job>>` where `Job` carries the chunk **and its destination sub-slice** (the `&mut [u8]` split happens once at drain start; the slice travels with the job so any drive's thread can write it) — read **directly into** it; on error: `ReplicaSlot::mark_degraded()` + set the thread's replica bit in `exclude_mask` + push the job back onto the **same drain-local list**, so a healthy drive's thread retries it within the same `wait()` (the global `ChunkQueue` only feeds new drains — a chunk parked there would deadlock the waiting drain). Fail the chunk with `StoreError::Unavailable` when `exclude_mask ⊇ healthy replicas of that shard` (health read once per decision, so a concurrent `mark_degraded` on another thread can't flip the predicate mid-check), and immediately when no eligible reader exists (the 1-replica case must fail, not hang). Spawn-cost arithmetic: 2 thread spawns ≈50 µs against a ≈1.76 ms two-drive drain of a 15.2 MB unit — ≈3%, and the cross-drive parallelism it buys is the point of §5.2. No persistent borrowed-state threads exist, so no `unsafe` and no lifetime hacks; in-flight chunks from prior drains are unaffected (each drain only owns its own reads' chunks).
  - `--io-threads` is a **new** flag (§5.4 names it but no task ever added it): `RunArgs` flag → `EngineConfig::io_threads: Option<usize>` field → `IoEngine`/drain thread count (default: derived 1–2 per drive).
  - New `PageRead` contract: `expected_crcs` is **per plane** (one entry per `read_plane` call), not per striped chunk — every existing `read_page` caller/test updates with this task. CRC is verified over the region after all of the plane's chunks land; mismatch → treat as corrupted replica (§5.3: mark degraded, same path as EIO) and `StoreError::Crc`.
- Consumes: `ChunkSource`/`ShardSources` traits, `ReplicaSlot::mark_degraded` (existing signatures).
