# M3.15 exclusive residency A/B (#64)

Real model GLM-5.3-Flash UD-Q4_K_XL, `--ram-experts-gib 57` (59 no longer
fits the 75%-of-available cap with the desktop running), K = 18 VRAM slots
per layer, 128 tokens, `scripts/ab-bench.sh`, binary at 33cc7d9. A =
`--residency inclusive`, B = `--residency exclusive`; A B B A then B A A B,
cold (`drop_caches` before each leg) and warm. Output byte-identical across
all 16 legs.

| leg | inclusive tok/s | exclusive tok/s |
|---|---|---|
| cold ABBA | 2.110, 2.176 | 1.636, 1.684 |
| cold BAAB | 2.056, 1.962 | 1.671, 1.758 |
| warm ABBA | 1.525, 1.590 | 1.607, 1.456 |
| warm BAAB | 2.018, 1.812 | 1.557, 1.579 |

Disk bytes per token: inclusive 1.16 GB, exclusive 1.13 GB (−2.6%) in every leg.

- Cold: inclusive 2.08 mean vs exclusive 1.69 (−19%), every exclusive leg
  slower than every inclusive leg.
- Warm: 1.74 vs 1.55 (−11%), within the ~20% run noise but same sign.
- The disk saving is far below the replay's d 18.0 → 13.8%: the replay
  modelled exclusive residency with a decayed RAM tier, the pool runs CLOCK
  (M3.7 decision), and dropped evictions (score floor) still go back to disk.
- The cost: every kept eviction's three planes go D2H on the split backend's
  stream ahead of the layer's H2D refills (≤18 × 15.2 MB ≈ 274 MB ≈ 11 ms
  per layer at 25 GB/s), so they sit on the critical path.

**Decision:** `--residency exclusive` stays opt-in; inclusive stays the
default (design O10). Revisit only with the D2H on a separate copy stream
and a decayed RAM tier.
