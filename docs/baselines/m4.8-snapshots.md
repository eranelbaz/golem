# M4.8 state snapshots — turn-N TTFT baseline

**Status: measured 2026-10-09** on this machine (24 GiB VRAM, 93 GiB RAM),
GLM-5.3-Flash UD-Q4_K_XL, `n_ctx` 4096, pool 57 GiB, snapshots 2 GiB.
Turn-5 TTFT: 49.6–52.6 s cold / 49.4–54.7 s warm without snapshots →
9.9–10.1 s cold / 9.8 s warm with them (≈ 5×). The greedy outputs of the
on and off runs are **not** byte-identical on the real model
(`outputs_equal_cold=false`, both orders); see Results.

## Arithmetic (real target)

Snapshot = 145.56 MiB recurrent + 19,712 B/token KV: 8k tokens ≈ 300 MiB,
32k ≈ 761 MiB, 100k ≈ 2.0 GiB. Floor = `parallel × snapshot_bytes(ctx)`;
default = `max(2 GiB, 2 × floor)`. RAM fit at 83 GiB free: 79 − (pool 63 +
staging 3.7 + host 2) = 10.3 GiB ≥ default 4.0 GiB at 100k / parallel 1.
Expected restore of ≈ 300 MiB from pinned memory ≈ 12 ms at 25 GB/s, vs tens
of seconds to re-prefill 8k tokens cold (§2.4). Pinned restore bandwidth is
unmeasured.

## Harness

`crates/golem-engine/tests/snapshot_tiny_moe.rs::hw_snapshot_turn_ttft`:
a 5-turn chat, `--snapshot-ram-gib` 0 vs 2, a fresh session each (cold pass),
then a second pass on the same session (warm). Page cache evicted before each
order with `scripts/evict-model-cache.py`.

```sh
M=~/models/glm-5.3-flash-ud-q4k-xl/UD-Q4_K_XL/GLM-5.3-Flash-UD-Q4_K_XL-00001-of-00006.gguf
python3 scripts/evict-model-cache.py "$(dirname "$M")"/*.gguf
GOLEM_HW=1 GOLEM_HW_MODEL=$M GOLEM_HW_ORDER=off,on \
  cargo nextest run -p golem-engine --features hip-tests --run-ignored all --no-capture hw_snapshot
python3 scripts/evict-model-cache.py "$(dirname "$M")"/*.gguf
GOLEM_HW=1 GOLEM_HW_MODEL=$M GOLEM_HW_ORDER=on,off \
  cargo nextest run -p golem-engine --features hip-tests --run-ignored all --no-capture hw_snapshot
```

Greedy output equality, on vs off: `false` in both orders. The tiny
fixtures are byte-identical. On the real model the delta prefill runs
different chunk shapes than a full re-prefill (routed-only fill, other
ubatch splits), so a GPU reduction-order divergence is the likely cause.

Follow-up (#84/#113, 2026-10-13): pooled prefill chunks are K / top_k tokens,
so the chunk shape follows the device cache K. A 48-token greedy dump at
K ∈ {8, 15, 16, 18} matches whenever K / top_k is equal (8 vs 15 and 16 vs 18,
both on UD-Q4_K_XL and UD-IQ4_XS). Going from 1- to 2-token chunks shifts top-1
logits by ≤ 0.47 and flips one near-tie token: gap 0.10–0.15 at step 36 / 40.
Snapshots on vs off over a 3-turn chat on IQ4_XS are identical at K = 8 (1-token
chunks) and differ at K = 18. Greedy output is therefore reproducible only for
a fixed chunk shape. `golem optimize` gates greedy output at §12.3 parity (equal
token streams up to a near-tie, top-1 − top-2 < 0.2), not on a byte hash.
